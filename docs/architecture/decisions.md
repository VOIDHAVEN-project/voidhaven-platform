# 实施决策登记

| 编号 | 决策 | 状态 | 说明 |
| --- | --- | --- | --- |
| ADR-V0-001 | React/Vite 与 Spring Boot 分离部署 | 已实施 | 同源 Nginx 在本地 Compose 中代理 Web 与 API。 |
| ADR-V0-002 | MySQL + Flyway 作为关系数据基线 | 已实施 | 所有状态、审计、审核及幂等记录通过可追溯迁移创建。 |
| ADR-V0-003 | S3 兼容私有媒体接口 | 已实施，待浏览器闭环 | 图片经服务端解码、重编码后进入私有 S3/MinIO；公开读取依赖已发布修订关联，写入凭据不进入浏览器。完整上传、发布、隐藏与清理链路仍需容器和浏览器证据。 |
| ADR-V0-004 | 生产云服务与域名 | 待单独批准 | 腾讯云、COS、域名、备案、邮件、监控接收人均不在当前执行范围。 |
| ADR-V0-005 | 候选修订与公开生命周期分离 | 已实施 | `workflow_status` 只表示当前候选修订的审核流程；`publication_status` 单独表示已发布版本的 ACTIVE/CLOSED 生命周期，避免编辑中的候选草稿阻断到期关闭与三日归档。 |
| ADR-V0-006 | 类型明细双写与 JSON 渲染投影 | 已实施 | 内容修订的竞赛规则/截止、资源类型、招募截止/关联竞赛/后续入口写入类型明细表；受控 JSON 只作富文本与前端渲染投影。自动到期处理以类型明细表为准，不能把 JSON 作为唯一业务字段来源。 |
| ADR-V0-007 | Markdown 创作优先与版本化内容模块注册表 | 已实施 | 管理员和合作方共用编辑器；Markdown 原文由服务端解析为安全文档 JSON。竞赛、团队招募、学习资源和文章/经验由 Git 版本控制的注册表驱动，发布修订保存定义快照；公开详情使用稳定 `/content/{id}`，旧分类路径兼容跳转。 |
| ADR-V0-008 | V0 生产形态为单机单副本 | 已更新 | 公开写入限流、登录/激活限流、生命周期/保留任务与媒体删除领取已改为 MySQL 共享状态。会话为 Spring Session JDBC。水平扩容必须先做非混合版本切换并完成单实例冒烟；首次生产切换默认保持 1 个 API。紧急回滚到旧镜像时也只能单实例。 |
| ADR-V0-009 | 生产冷启动走显式一次性激活命令 | 已实施，待候选验证 | 普通 production Web 进程不创建账号或输出激活材料；授权操作者必须单独运行 `production,bootstrap-admin` 无 Web 命令，在事务提交后仅向当前终端输出一次性激活链接。角色由 Flyway V8 种子。 |
| ADR-V0-010 | SEO 基线先于 SSR | 已实施 | V0 提供动态标题、robots、sitemap 与 ErrorBoundary；纯 SPA 预渲染列为上线后议题。 |
