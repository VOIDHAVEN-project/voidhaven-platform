# 测试服务器发布手册

本手册只适用于使用合成账号和非敏感内容的临时测试环境。执行上传、SSH、启动、回滚或切换服务器指针前，必须再次获得明确授权。

## 发布输入

- 干净的 Git 提交或 annotated tag。
- 完整 Git SHA、版本号、UTC 构建时间和不可变镜像标签。
- `infra/compose/compose.test-server.yml`。
- 服务器本地 `0600` Secret 文件；Secret 不进入发布包、Git、日志或聊天。
- 最近一次可恢复备份和上一验证镜像。

## 发布门禁

1. 在干净 clone 中完成 Web、API、OpenAPI、Compose、集成测试和浏览器验收。
2. 生成发布清单、配置/迁移校验值、发布包 SHA-256 和已知限制。
3. 人工确认维护窗口、影响范围、备份、回滚版本和责任人。
4. 只从版本化源码构建，不再复制 `work/` 或 `sources/` 目录生成新版本。
5. 测试服务器仅由网关暴露端口；MySQL、MinIO、API 和 Web 不直接发布宿主机端口。

## 回滚原则

- Web 或 API 独立故障优先回滚对应不可变镜像。
- 数据迁移采用扩展后收缩；不得把不可逆删除作为常规发布步骤。
- 回滚后重新验证 `/healthz`、公开首页 API、首页、登录和权限拒绝。
- 禁止为回滚执行 `docker compose down -v` 或删除命名数据卷。
