# 特权账号恢复与安全切换

## 切换

先验证数据库迁移和应急恢复路径，停止旧应用实例，运行追加迁移后启动新版本；禁止新旧安全版本混跑。旧会话与未使用激活/恢复链接失效，通知重新登录和重新签发。普通管理员需要超级管理员重新授权。保留新增结构；不得回退到接受旧凭据或 ADMIN 默认全权的版本。

## 超级管理员恢复

仅经批准的运维人员在受控主机、交互终端运行独立应用进程，设置 `spring.main.web-application-type=none`，启用 `recover-super-admin` 与 `production` 或隔离的 `test-server` 环境。只提供 `--login`、`--operator`、`--reason`；密码在控制台隐藏输入两次。不得通过参数、环境变量、管道或日志提供密码。真实环境配置通过既有受控运维配置加载，不复制到源码仓库。

命令只恢复已有正常或待激活超级管理员（包括初始化链接过期）；停用/撤销账号拒绝恢复，不创建账号。失败整体回滚。`operator` 是审计标签，身份授权以实际主机访问身份及运维记录为准。普通 Web 进程不可启用恢复 profile；启动检查会拒绝 Web 模式。

在已批准主机中，使用当前发布包运行，例如：

```powershell
$env:SPRING_PROFILES_ACTIVE='production,recover-super-admin'
$env:SPRING_MAIN_WEB_APPLICATION_TYPE='none'
java -jar <当前发布包.jar> --login=<既有超级管理员登录名> --operator=<运维身份标签> --reason=<恢复原因>
```

示例不包含数据库配置；沿用受控主机的批准配置。执行结束后清除本次 profile 环境变量。此命令不注册新账号，不执行初始化。

恢复后先验证新登录，再核查管理员授权、账号创建、激活/恢复签发历史；撤销异常账号和授权，并检查受影响组织和内容。禁止删除证据。有效超级管理员凭据失窃仍可能造成合法权限范围内的修改，本轮不引入 MFA 或双人审批。
