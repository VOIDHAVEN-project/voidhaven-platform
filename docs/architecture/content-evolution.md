# 编辑系统与内容模块演进手册

本文规定 VOIDHAVEN 如何低成本调整内容字段和栏目，同时保留历史内容、审核与安全边界。模块定义随 Git 版本发布，不允许运营人员在生产后台直接修改数据结构。

## 稳定内核

所有内容模块共享同一个内容项、候选修订、审核、发布、审计、媒体与安全 404 内核。`module_key` 标识模块；`schema_version` 与 `schema_snapshot_json` 保证旧修订在注册表变化后仍可解释。正文同时保存作者的 `markdown_source` 与服务端生成的版本化安全 `body_json`，浏览器不渲染任意 HTML。

当前注册表位于 `apps/api/src/main/resources/content-modules.v1.json`，包含 `competition`、`recruitment`、`resource` 和 `resource.article`。文章/经验仍属于学习资源，不增加独立公开导航。

## 变更流程

1. 在新版本注册表中调整字段、模板或模块状态，递增顶层 `version`。
2. 判断变更是否只影响展示元数据，还是影响来源、权限、审核、配额、到期或媒体策略。
3. 对影响业务规则的变更同步修改后端策略、OpenAPI 与自动化测试；需要持久化结构时使用新的 Flyway 迁移，禁止修改已经发布的迁移。
4. 验证空库迁移、从上一版本升级、模块定义加载、前端构建、旧内容读取与完整审核流程。
5. 发布后保留旧修订的定义快照；回滚应用版本时不得回滚已经写入的数据迁移。

## 常见调整

| 调整 | 做法 | 数据迁移 |
| --- | --- | --- |
| 改文案、帮助、顺序或枚举选项 | 修改注册表并补兼容测试 | 通常不需要 |
| 新增非筛选字段 | 注册表声明，值进入 `metadata_json` | 通常不需要 |
| 新增筛选字段 | 注册表标记 `filterable`，发布修订写入 `revision_filter_values` | 通常不需要 |
| 新增模块 | 添加模块定义、公开卡片/详情适配、契约和闭环测试 | 通常不需要 |
| 改首页、导航、卡片布局 | 修改 React 页面与样式并常规发布 | 不需要 |
| 改来源、权限、配额、到期或审核 | 修改后端策略、契约和测试 | 视业务结构决定 |
| 停用字段 | 新版本不再编辑，历史快照继续显示 | 不立即删除 |
| 停用模块 | 将模块设为不可新建并移除入口，历史内容保留读取或受控归档 | 不立即删除 |

字段键和模块键一旦有公开数据即视为稳定标识。重命名显示文案不应改键；确需换键时，应新增键、迁移投影并保留旧键读取兼容。

## Markdown 与媒体规则

- 支持标题、段落、强调、HTTPS 链接、引用、列表、代码块、分隔线和 `media:<id>` 图片引用。
- 拒绝原始 HTML、脚本、事件属性、远程图片和危险协议；预览不是发布依据，保存与送审以服务端解析结果为准。
- `.md` 导入上限为 256 KiB；导出仅包含当前草稿正文，不包含凭据或本机路径。
- 新修订只继承正文仍引用且已归属当前修订的媒体，并按 Markdown 顺序重建关联；跨内容媒体 ID 会被拒绝。
- 已发布内容编辑时创建候选修订，旧公开修订持续可见，直到新修订审核通过并发布。

## 来源与兼容路由

竞赛仍必须提供可核验的 HTTPS 官方规则。普通资源和外部文章必须提供原始来源；`resource.article` 可选择原创，但必须提供作者展示名和权利声明。引用材料仍应使用 HTTPS 链接。

公开详情的唯一稳定地址是 `/content/{id}`。旧 `/competitions/{id}`、`/resources/{id}` 与 `/recruitments/{id}` 只承担兼容跳转，新增分享入口不得继续生成分类详情 URL。

## 发布门禁

模块定义变更至少需要通过：注册表启动校验、后端单元测试、Flyway 空库与升级迁移、OpenAPI 校验、前端静态检查/测试/构建，以及管理员或合作方从草稿到公开的端到端验证。若 Docker、浏览器或外部测试环境不可用，相关门禁必须记录为未验证，不能默认为通过。
