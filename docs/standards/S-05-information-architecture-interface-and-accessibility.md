## 1. 目的与适用边界

本规范把已批准的产品范围和数据边界，转换为可审阅的页面、导航、组件、状态、响应式和可访问性要求。它的目的不是先把页面“画得完整”，而是让后续模块开工前能够回答：

1. 每个用户从哪里进入、能看到什么、下一步去哪里；
2. 哪些页面面向公开访客，哪些只面向合作方或管理员；
3. 富文本、来源、语言、权利说明、审核状态和受控社群入口应怎样被看见；
4. 原始 Notion 风格原型的哪些视觉关系要保留，哪些旧产品含义必须停止继承；
5. 手机、键盘和辅助技术用户是否仍能完成同一件事。

本规范不选择编辑器库、路由库、后端框架、媒体存储供应商或登录供应商；它也不授权直接修改 `D:\Projects\voidhaven` 的代码。接口字段、权限检查和错误响应由 S-06 细化，测试由 S-07 细化，部署与实际外部入口由 S-08 细化。

## 4. 信息架构与路由规范

### 4.1 路由分区

公开路由必须无需普通学生账号即可访问。合作方和管理员路由不是公开导航栏目；它们要求受限账户和服务端权限校验。

| 分区 | 规范路由 | 页面责任 | 可访问主体 |
| --- | --- | --- | --- |
| 公开发现 | `/` | 让访客快速发现竞赛、资源与团队招募 | 所有公开访客 |
| 公开发现 | `/competitions`、`/competitions/:id` | 浏览、筛选、核验竞赛及其官方来源 | 所有公开访客 |
| 公开发现 | `/resources`、`/resources/:id` | 浏览资源、文章、项目和外部知识入口 | 所有公开访客 |
| 公开发现 | `/recruitments`、`/recruitments/:id` | 浏览已核验合作方发布的团队招募和受控后续入口 | 所有公开访客 |
| 公开贡献 | `/submit` | 提交内容线索、资源、经验、项目、竞赛线索、版权/侵权反馈或改进反馈 | 所有公开访客 |
| 公开贡献 | `/partners/apply` | 申请成为持续发布内容的可信合作方 | 所有公开访客 |
| 公开说明 | `/join` | 通过低门槛验证进入校内社群，并了解参与项目建设的方式 | 所有公开访客；社群信息仅向通过验证者显示 |
| 公开说明 | `/about` | 项目定位、责任边界、阶段和开源说明 | 所有公开访客 |
| 受限会话 | `/sign-in` | 合作方/管理员的受限登录入口；不在公开 Header 中展示 | 已获邀或已获批的合作方、管理员 |
| 合作方管理 | `/partner`、`/partner/content/new`、`/partner/content/:id/edit` | 查看本人内容、配额、审核状态，编辑候选内容并提交审核 | 仅对应 PartnerProfile 的合作方 |
| 管理后台 | `/admin`、`/admin/reviews`、`/admin/content/:id`、`/admin/partners`、`/admin/settings` | 审核、发布、隐藏、归档、代录、归属转交、配额和必要审计 | 管理员/超级管理员，按职责细分 |
| 全局状态 | `*` | 404、无权限、受控错误与返回有效路径 | 与请求上下文一致 |

`/recruitments` 是已裁决的团队招募规范路由。旧 `/teams` 不再承载新的双向组队含义；若实施时确认存在既有外链，则做一次明确的兼容跳转。`id` 表示对用户和前端不透明的公开标识，具体格式由 S-06 约束。

### 4.2 Header、Footer 与入口纪律

**已批准公开 Header**：品牌链接、竞赛、资源、团队招募、投稿/反馈、加入我们、关于。桌面端显示完整导航；移动端折叠为可键盘操作的菜单。

**不出现在公开 Header 中的内容**：普通学生登录/注册、个人资料、私信、聊天、评论、人才库、管理员入口、合作方后台、未审核内容和私人联系方式。已获批的合作方或管理员可经直接受控链接进入 `/sign-in`；这不把站点变成面向普通访客的账户产品。

**Footer** 保持文字优先、低对比度、可压缩的视觉风格，并分为：

- 探索：竞赛、资源、团队招募；
- 贡献：投稿/反馈、合作方申请；
- 项目：加入我们、关于、经确认的 GitHub/公开项目入口；
- 说明：版权/侵权反馈入口、必要隐私说明和版权信息。

未配置的外部入口必须表达“暂未开放”或给出可解释的站内替代路径；不能渲染一个无反应按钮，也不能为填满 Footer 虚构社群链接。

## 5. 页面规范

### 5.1 首页 `/`

**目标**：访客在 3–5 秒内理解这里可以发现学习资源、竞赛信息和由已核验合作方发布的团队招募，并在首屏或很短滚动内看到真实公开内容，而不是项目宣言。

**结构**：

1. 全局 Header；
2. 紧凑 Hero：英文 slogan、中文产品说明、两个不夸张的主要 CTA；
3. 首个信息区：`近期竞赛 / 团队招募` 两栏展示；两个栏目各自拥有同级栏目入口与“查看全部”；
4. 第二个信息区：以同等级标题展示“学习资源”的横向/全宽列表，并提供其独立栏目入口与“查看全部”；
5. 公开贡献 CTA，指向投稿/反馈；
6. 全局 Footer。

“近期竞赛”“团队招募”“学习资源”都是一级栏目；桌面端的前后分区只服务于原型的两栏视觉节奏，不表示学习资源从属竞赛或招募。推荐 Hero 主操作为“浏览竞赛”，次操作为“探索资源”；团队招募通过同级真实信息模块和 Header 清晰可达。不得继续使用“寻找队伍”暗示学生公开找队市场。

三个栏目都须支持独立 Loading、Success、Empty、Error，任一栏目失败或为空都不得让整个首页坍塌。桌面端按“近期竞赛、团队招募、学习资源”布局；移动端按“近期竞赛、学习资源、团队招募”单列展示。每个栏目都包含同级栏目入口与“查看全部”；首页只展示经公开可见性与生命周期规则筛选后的内容。

### 5.2 竞赛列表与详情

**列表 `/competitions`**：页面标题、简短说明、可用的分类/公开状态/语言筛选、结果数、按时间紧迫度排序的列表，以及 Loading/Empty/Error。首发不建设热度排序、个性化推荐或无证据的复杂搜索。每条列表项至少让用户判断：竞赛是什么、是否仍可参与、关键时间、官方来源是否可用、是否存在已公开关联团队招募。

**详情 `/competitions/:id`**：

1. 标题、分类、语言标签、公开业务状态与关键时间；
2. 适用对象和资格摘要；
3. 官方网站、报名入口、通知/文件等可核验来源；
4. 连续说明正文或规则摘要，并清楚提示“以官方规则为准”；
5. 可选的关联团队招募区；
6. 来源、最后更新和版权/侵权反馈入口。

不存在、隐藏或无权公开的详情统一呈现为不泄露内部状态的 404；不能将待审核、已删除或私人信息误显示为普通 Empty State。

### 5.3 资源列表与详情

**列表 `/resources`**：资源类型（文章、外部链接、项目、视频、文档、经验）、语言、结果数、列表卡片和状态面板。是否增加主题词/标签筛选，应在已有真实内容形成稳定分类后再决定；本批不凭空创建庞大分类树。

**详情 `/resources/:id`**：以连续文章或资源阅读页为主体，顶部和尾部使用结构化信息区块，不退化为一串表单字段。页面至少呈现：

- 标题、资源类型、语言标签；
- 非中文内容的原始标题、中文导读/摘要和原始来源；
- 作者展示名、来源/权利来源、阅读与复用声明；
- 安全渲染的富文本正文、经处理的图片、外部链接；
- 关联竞赛（如有）和最后更新时间；
- 统一的版权/侵权反馈入口。

阅读公开内容不要求账户。下载、导出或一键转载不是首发页面必需功能；页面不得把可阅读自动写成“可自由转载、下载或改编”。

### 5.4 团队招募列表与详情

**列表 `/recruitments`**：展示已核验合作方公开的团队招募，不展示学生个人找队信息。每项至少包含：标题、合作方公开展示名、角色/能力要求、可选关联竞赛、截止时间、当前公开业务状态、语言标签和受控下一步提示。禁止直接显示微信、QQ、手机号、私人邮箱、群二维码或站内应聘记录。

**详情 `/recruitments/:id`**：展示团队招募背景、责任主体、角色/能力要求、投入或协作说明、截止时间、可选关联竞赛、来源/更新信息及受控下一步操作。用户的下一步只能进入相同规则的校内社群验证入口或已审核的外部渠道；站内不收集简历、报名、聊天、面试或申请记录。若团队招募已结束，应清楚显示“已结束”；到期后的可见性和归档仍完全由 S-04 控制。

### 5.5 投稿/反馈 `/submit`

该页是所有公开访客实际可用的提交入口，而不是旧 V0 的静态说明页。支持的可选类型为：竞赛线索、学习资源、经验/文章、项目、一般反馈和版权/侵权反馈。团队招募发布不在本入口完成；希望持续发布竞赛、团队招募或资源的主体进入合作方申请页。

页面结构为：用途与审核说明 → 类型选择 → 动态最小表单 → 提交前隐私/留存说明 → 表单状态与下一步。表单不得要求普通账号，不得在公开页面回显私人联系方式，也不得给未审核内容生成公开详情页。

用户可见状态必须是中文且可区分：编辑中、校验失败、提交中、提交成功、提交失败、已识别为重复提交。网络重试须复用同一逻辑提交，不能让用户因刷新或双击制造多条业务记录。

### 5.6 合作方申请 `/partners/apply`

该页与投稿页分开。它解释申请对象、核验方式、可获得的受限能力、私密联系信息用途和留存期；申请表只收集核验所需最小信息。提交成功仅表示进入人工核验，不等于自动注册、自动获得 PartnerProfile 或可立即发布公开内容。

### 5.7 加入我们 `/join`

页面首要模块是“校内社群入口”：说明其仅用于校内目标人群的低摩擦验证、不会建立普通学生账号、验证后才显示受控入群信息。验证 UI 必须覆盖空值/格式提示、回答不匹配、提交中、网络失败、安全重试、短时限流和冷却状态；不得透露正确答案、完整限流规则或群二维码。

页面次要模块可以保留项目共建角色、开源协作和经确认的 GitHub 入口。它们不应被表述为招聘 ATS、简历收集或站内申请流程。

### 5.8 关于 `/about`

承载完整项目故事：名称、发起背景、网站与社群边界、为什么资源/竞赛/团队招募并列、当前阶段和公开项目入口。首页只保留极短的定位说明，不回流大段品牌叙述。

### 5.9 受限合作方与管理员界面

受限页面不是普通用户功能，也不必复制公开站的营销式排版；但应继承同一套中性色彩、排版、状态和可访问性规则。

| 页面 | 最小信息与动作 | 禁止事项 |
| --- | --- | --- |
| 合作方工作台 | 本人 PartnerProfile、活跃公开内容计数/配额、本人候选内容及审核状态 | 查看其他合作方私密信息、越过审核直接公开。 |
| 内容编辑器 | 结构化元数据、富文本正文、受限图片、来源/权利/语言、预览、保存草稿、提交审核 | 把关键字段只藏在正文；允许危险嵌入或任意文件上传。 |
| 管理审核队列 | 对象类型、来源、完整性缺口、审核结论、必要私密资料的受控查看、发布/隐藏/归档动作 | 在公开列表或普通管理页暴露联系方式、完整私密正文或不必要审计上下文。 |
| 合作方与配额管理 | 核验状态、账号状态、PartnerProfile、0–5 的例外配额、归属转交审计 | 将后台备注 `affiliationLabel` 公开化或拿来判断编辑权限。 |

## 6. 视觉系统与组件基线

原始 Notion 风格原型的视觉关系被采用为本规范的默认基线。以下数值是可实现的起始 token，不声称为原始设计稿的精确像素；若后续改动会改变“浅色、克制、编辑式、信息优先”的关系，应通过本规范或 DR 说明。

| 类别 | 默认基线 |
| --- | --- |

## 7. 响应式、状态与可访问性

### 7.1 响应式

- 桌面：优先使用居中壳层；首页首个信息区固定为“近期竞赛 / 团队招募”两栏，随后显示全宽“学习资源”；详情页以可读的单主体内容为主，不强行套首页双栏。
- 平板：在内容仍可读时保留双栏，否则宁可提前收为单栏，不能压缩到标题、操作和元数据互相遮挡。
- 移动端：主导航折叠为菜单；首页按“近期竞赛、学习资源、团队招募”单列展示；列表单列；Hero 操作纵向或可换行；重要状态、截止时间和 CTA 不依赖悬停才能发现；页面不得横向滚动。
- 内容韧性：必须容纳长标题、长中文导读、缺失可选字段、0/少量/大量结果和不同手机宽度。省略次要信息前先保留标题、公开状态、关键时间和下一步。

### 7.2 通用状态

数据型区域至少覆盖 Loading、Success、Empty、Error；详情额外覆盖 Not Found；受限页面额外覆盖 Unauthorized/Forbidden。状态面板是页面内语义状态，而非新业务页面；Header、Footer 和返回有效路径在适用时仍可用。

表单统一使用 DR-002 已批准的六类状态。错误提示必须指出用户能否修正、能否重试和下一步，而不直接展示后端英文、堆栈、私密字段或风控规则。

### 7.3 可访问性最低要求

1. 使用语义化 `header`、`nav`、`main`、`footer`、`article`、`section`、标题层级、`label`、`fieldset` 和真实 `button`/`a`；
2. 所有主要操作可用键盘完成，菜单、筛选、表单、上传、提交状态和错误焦点顺序可预测；
3. 焦点样式始终可见，不能只依赖颜色区别选中、错误、已结束或禁用；
4. 图片需有与内容相关的替代文本；装饰图片可空替代；富文本内图片的替代文本是内容编辑的必要字段；
5. 表单错误与异步结果以可读文本和适当的 live region 告知，不能只用图标、红色或 Toast；
6. 外部链接清楚提示其会离开本站；受控社群入口在验证前不得把私密地址写入 DOM、静态源码或可复制提示；
7. 页面语言为简体中文；外语原文保留自身语言语义，中文导读明确不是全文翻译。

## 8. 明确不做的 UI

- 普通学生登录、注册、个人主页、简历、人才库、公开找队帖；
- 站内聊天、私信、评论、点赞、收藏、报名、面试和社群行为记录；
- 为补足首页而虚构热门排行、AI 推荐、空数据推荐或未核验内容；
- 公开展示私人联系方式、群二维码、投稿私密联系信息、审核意见、后台备注或操作日志；
- 将任意文件、视频、网盘代存、自动抓取或下载/转载工具伪装为“资源页面”的默认能力；
- 把管理后台入口伪装成普通用户功能，或因视觉参考而删除实际产品必须的资源、投稿、合作方申请和隐私说明。
